# Kroshka

**Семейный мессенджер для локальной сети.** Свой сервер, свои комнаты, своя история —
и ничего наружу.

<p align="center">
  <img src="docs/img/logo-512.png" width="128" alt="Kroshka">
</p>

Kroshka — это альтернатива Telegram для дома: ставится на один компьютер в квартире,
поднимает сервер, остальные подключаются по локальной сети (или через ZeroTier, если
кто-то далеко). Ни аккаунтов в облаке, ни подписок, ни телеметрии. Все данные лежат
в обычных файлах на вашем диске.

## Быстрый старт

### Вариант 1: один компьютер на всю семью

1. Скачайте `kroshka-client-win-x64.zip` из [Releases](../../releases).
2. Распакуйте в любую папку и запустите `Kroshka.exe`.
3. Клиент сам поднимет сервер на `6767` и откроет окно.

Всё. Второй член семьи открывает `http://<ip-хозяина>:6767` в браузере или ставит
клиент и в настройках выбирает «Подключаться к серверу в сети».

### Вариант 2: отдельный сервер

```powershell
# распакуйте kroshka-server-win-x64.zip
.\KroshkaServer.exe
```

Или на Linux:

```bash
tar -xzf kroshka-server-linux-x64.zip
./KroshkaServer
```

Сервер напишет в консоль свой адрес в сети:

```
  адрес: http://192.168.1.10:6767/
  админ: http://192.168.1.10:6768/admin
```

### Открыть порт в брандмауэре

Без этого шага соседи по сети не подключатся. PowerShell **от администратора**:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\firewall.ps1
```

Скрипт добавляет правила для `6767` (чат) и `6768` (админка). Убрать — `-Remove`.

## Настройка

Всё живёт в `config.ini` рядом с исполняемым файлом. Полный файл с комментариями —
[`config.example.ini`](config.example.ini). Скопируйте его в `config.ini` и правьте.

### Кто может войти

```ini
[auth]
; open      — ввёл ник и зашёл. По умолчанию, для дома.
; password  — ник + общий пароль семьи.
; invite    — ник + код, который вы выдаёте (удобно для друзей через ZeroTier).
mode = open
allowRegister = true
```

В любом режиме устройство **запоминается**: вошёл один раз — и дальше приложение
открывается сразу. Токен устройства хранится в профиле и отзывается одной кнопкой,
если телефон потерялся.

### Дом для друзей через ZeroTier

1. Поставьте сервер на машину, которая всегда включена.
2. В `[auth]` включите `mode = invite` и задайте `inviteCode`.
3. В ZeroTier дайте друзьям доступ к сети.
4. Отправьте им адрес `http://<zerotier-ip>:6767` и код.

### Свои цвета

```ini
[branding]
accent = #0088FF
accentHi = #0080FF
accentLo = #0066CC

darkBg = #0A0F1A
darkPanel = #111A29
oledBg = #000000
```

Всё остальное — в админке, на вкладке «Настройки». Изменения оттуда пишутся в
`data/overrides.json` и перекрывают `config.ini`, не трогая ваши комментарии.

### Выключить лишнее

У каждой функции есть выключатель. Если семье не нужны голосовые:

```ini
[features]
voice = false
```

Кнопка исчезнет из интерфейса, а сервер начнёт отвечать `403` на соответствующие
запросы — никакого «наполовину работающего» UI.

## Как это устроено

```
Kroshka/
├─ src/
│  ├─ DPT.Kroshka.Shared/   модели, протокол, конфиг, лог, файловые утилиты
│  ├─ DPT.Kroshka.Server/   Kestrel, REST + WebSocket, хранилище, админка
│  └─ DPT.Kroshka.Client/   WinForms + WebView2 + трей
├─ web/                     ОДИН интерфейс для десктопа, браузера и будущего Android
│  ├─ assets/css/           app.css (три темы), admin.css
│  ├─ assets/js/            api, ui, sound, app, admin
│  └─ vendor/fontawesome/   полный офлайн-пакет
├─ android/                 план мобильного клиента
├─ tools/                   firewall.ps1, make-ico.ps1
└─ docs/                    архитектура и решения
```

### Данные на диске

Никакой SQL. База — это папки и файлы, которые можно открыть блокнотом:

```
data/
  users/<id>/user.json
  rooms/<id>/room.json
  rooms/<id>/msg/2026-11.ndjson     ← по одному файлу на месяц
  dm/<id>/dm.json
  dm/<id>/msg/2026-11.ndjson
  blobs/<ab>/<sha256>.png           ← контент, дедуплицирован по хэшу
  blobs/<ab>/<sha256>.json          ← имя, mime, размер
  sessions.json
  backups/20261121-134500/          ← снимок всей папки
```

Сообщения пишутся **append-only**: одна строка JSON на сообщение. Сбой питания
стоит максимум последней строки — остальное целое. Правка сообщения переписывает
только файл своего месяца, атомарно, через временный файл и `.bak`.

### Живые события

REST — для команд и истории, WebSocket — для всего, что происходит сейчас:
новые сообщения, реакции, «печатает…», присутствие, закрепления.

У медленного клиента очередь ограничена 512 кадрами. Переполнилась — сокет
закрывается, клиент переподключается и досинхронизируется. Это лучше, чем тихо
отставать навсегда.

### Отказоустойчивость

- Атомарная запись любого документа (temp → replace → `.bak`).
- Битый файл не роняет сервер: он карантинится в `.bad-<дата>`, остальные живут.
- `UnhandledException` и `UnobservedTaskException` пишут crash-лог и не убивают процесс.
- Если порт занят, сервер пробует следующие из `portFallbacks`.
- Обслуживание (чистка сессий, бэкап) падает молча в лог, а не в сервер.

### Логирование

Через `System.Diagnostics.Trace`, настроенный **из кода** — без `App.config`.
`Log.Configure()` идемпотентен: повторный вызов снимает прежний листенер, поэтому
строки не задваиваются. Файлы в `logs/`, ротация по дню и размеру, старые удаляются.

## Сборка из исходников

Нужен только [.NET 10 SDK](https://dotnet.microsoft.com/download).

```powershell
build.cmd            # Release, требует установленный .NET 10
build.cmd self       # self-contained: win-x64 и linux-x64
build.cmd publish    # готовые архивы в artifacts\
build.cmd test       # внутренние тесты хранилища
build.cmd clean
```

Тесты — это не формальность: они проверяют атомарную запись, восстановление из
`.bak`, чтение NDJSON после обрыва, дедупликацию файлов и жизненный цикл сессий.
98 проверок, все зелёные.

### Разработка

```powershell
dev-server.cmd       # сервер на живых файлах web\
dev-server.cmd stop
```

Правьте `web/`, обновляйте страницу — сервер подставит свежий токен версии сам.

### Тестовые данные на живом сервере

Если проверяете что-то на работающем сервере, создавайте аккаунты с префиксом
`test` — `test1`, `test2`, `test-комната`. Тогда уборка будет одной командой:

```powershell
# посмотреть, что удалится (ничего не трогает)
tools\clean-test-data.ps1 -Data bin\server\data

# удалить аккаунты test* и их личные сообщения
tools\clean-test-data.ps1 -Data bin\server\data -UsersOnly -Apply

# плюс комнаты test*
tools\clean-test-data.ps1 -Data bin\server\data -TestRooms -Apply

# полная очистка перед запуском «в бой»
tools\clean-test-data.ps1 -Data bin\server\data -Everything -Apply
```

Скрипт откажется работать, пока сервер слушает порт: удалять файлы под живым
сервером — верный способ получить воскресшие данные.

## Админка

Отдельный порт (`6768`), отдельный пароль. На публичном порту `/api/admin/*`
не существует вообще — утёкшая ссылка на чат не даёт доступ к панели.

| Вкладка | Что делает |
|---|---|
| Обзор | Люди, комнаты, сообщения, размер данных, предупреждения конфига |
| Люди | Создать, переименовать, сменить роль, забанить, удалить |
| Комнаты | Создать, удалить вместе с историей |
| Настройки | Имя, тема, цвета, режим входа, функции — без правки файла |
| Обслуживание | Бэкап, сжатие журналов, удаление старого, чистка вложений |
| Логи | Живой хвост лога с уровнями |

## Android и Linux

**Linux-сервер** собирается уже сейчас (`build.cmd self`) и работает headless.
**Linux-клиент** — следующий шаг: тот же `web/`, обёрнутый в GTK-WebKit.

**Android** — в [`android/`](android/README.md) лежит план: `.NET 10 Android` +
WebView с тем же интерфейсом и мост на `@JavascriptInterface`, как в AutoZapret.
Протокол уже готов: REST + WebSocket, ничего дописывать не придётся.
