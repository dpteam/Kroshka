# Архитектура Kroshka

Короткий документ о том, **почему** сделано так, а не иначе. Код читается, решения —
нет, поэтому они здесь.

---

## 1. Почему Kestrel, а не свой HTTP-сервер

В DPT Social сервер написан на сокетах вручную: там это было вынужденно (нужен
.NET 4 и XP). У нас .NET 10, и ручной HTTP-парсер — это чистый убыток: свои баги в
chunked-кодировании, свои дыры в разборе заголовков, свой велосипед для WebSocket.

Kestrel даёт:

- WebSocket из коробки (для чата это принципиально — long-polling на 48 потоках,
  как в Social, не масштабируется на «печатает…» и присутствие);
- корректные таймауты, keep-alive, backpressure;
- range-запросы для аудио и видео (перемотка голосового работает бесплатно).

Цена — зависимость от ASP.NET Core. Она входит в SDK, отдельный NuGet не нужен.

## 2. Почему файлы, а не SQLite

Требование было прямым: «по-простому без SQL, файлами и папками».

Оказалось, что для чата это ещё и хорошо:

| | SQLite | Файлы |
|---|---|---|
| Правка истории руками | нужен клиент | блокнот |
| Бэкап | `VACUUM INTO` или копия с блокировкой | копия папки |
| Сбой питания | WAL, обычно ок | теряется последняя строка |
| Восстановление | целостность БД или ничего | битый файл карантинится, остальное живёт |
| «Сжать базу» в админке | осмысленно | честная перепаковка NDJSON |

Единственное, что файлы делают плохо, — поиск по всей истории. Поэтому поиск
читает только те логи, что уже в памяти, и ограничен 100 результатами. Для семьи
этого достаточно; для тысяч пользователей понадобился бы индекс.

### Почему NDJSON, а не один JSON на диалог

Один файл на диалог означает: каждое новое сообщение переписывает всю историю.
С чатом на 50 000 сообщений это 20 МБ записи на одну реплику.

NDJSON (одна строка — одно сообщение) позволяет `append`. Дописывание в конец
файла атомарно на уровне ОС для небольших записей, а если питание пропадёт
посреди строки — при чтении эта строка просто не распарсится и будет пропущена.
Файл при этом остаётся валидным.

Разбивка по месяцам (`2026-11.ndjson`) держит файлы маленькими и делает «удалить
всё старше года» операцией уровня «удалить несколько файлов».

### Почему правка переписывает месяц

Изменить одну строку в середине файла нельзя, не переписав хвост. Поэтому правка
переписывает только файл своего месяца — атомарно, через temp + replace. Месяц
обычно 1–5 МБ, это доли секунды. Альтернатива (tombstone + отдельный журнал правок)
дала бы сложность, несовместимую с «открой в блокноте и пойми».

## 3. Дедупликация вложений

Файл хранится под своим SHA-256:

```
data/blobs/ab/abcdef...123.png
data/blobs/ab/abcdef...123.json   ← имя, mime, размер, размеры картинки
```

Одна и та же фотография, отправленная в три комнаты, занимает одно место. Это не
оптимизация ради цифры: в семейном чате пересылают одни и те же фото постоянно.

Удаление — только через админку («очистить файлы»), потому что нужно проверить,
что на блоб больше никто не ссылается. Ссылки собираются из всех логов сообщений
плюс из аватаров.

### Определение размеров картинки без System.Drawing

`ImageProbe` читает заголовки PNG, GIF, BMP, JPEG и WebP вручную. Причины:

1. `System.Drawing.Common` на Linux требует `libgdiplus` — лишняя внешняя зависимость
   для self-contained сборки.
2. Нам нужны только ширина и высота, а не декодирование пикселей.
3. Пять форматов — это ~80 строк, которые невозможно сломать обновлением рантайма.

## 4. Идентичность и сессии

### Ник как вход

В режиме `open` ник — это и логин, и идентичность. Пароля нет вообще. Это
сознательно: требование «альтернатива Telegram для семьи в локалке» несовместимо
с формой регистрации на десять полей.

Защита от подмены: ник уникален без учёта регистра (`NickLower` — отдельное поле,
чтобы не зависеть от коллации файловой системы).

### Токен устройства

```
клиент ←──────────── token (один раз, base64url, 256 бит)
сервер: sessions.json → { tokenHash: SHA256(token), device, ip, expires }
```

На диске **нет** самого токена. Копия `sessions.json` не даёт войти. Сравнение —
`CryptographicOperations.FixedTimeEquals`, чтобы не течь по времени.

«Запомнить меня» = 365 дней. Профиль показывает все устройства и позволяет отозвать
любое — это и есть кнопка «я потерял телефон».

### Пароль семьи

`auth.mode = password` — один общий пароль на всех. Это не аутентификация
пользователей (её нет), а барьер от случайного соседа в той же Wi-Fi сети.
Хранится в конфиге открытым текстом, потому что он и так один на всех и меняется
владельцем.

Пароли отдельных аккаунтов (на будущее) хэшируются PBKDF2-SHA256, 120 000 итераций,
соль на пользователя, итерации записаны в сам хэш (`120000$base64`), чтобы можно
было поднять стоимость без миграции.

## 5. WebSocket и почему не long-polling

Одна розетка на окно, все события по ней.

```
сервер → ready, message, message.edited, message.deleted, reaction,
         typing, presence, read, pinned, room.*, dm.created, user.updated
клиент → subscribe, unsubscribe, typing, ping, call.signal
```

Клиент при подключении автоматически подписывается на все доступные диалоги:
значки непрочитанных и уведомления должны работать без явных подписок.

### Backpressure

У каждого соединения очередь на 512 кадров. Если клиент не успевает — сокет
закрывается (`Abort`), клиент переподключается и досинхронизируется. Это честнее,
чем держать в памяти неограниченную очередь для зависшего вкладки.

### Ресинк после обрыва

При переподключении клиент не доверяет своей памяти: он запрашивает хвост активного
диалога и доливает всё, чего не хватает по `seq`. `seq` — монотонный номер внутри
диалога, он же курсор пагинации.

### Сигналинг звонков

`call.signal` уже маршрутизируется: сервер пересылает `Data` как есть, не заглядывая
внутрь. Когда дойдёт до WebRTC, менять протокол не придётся — только включить
`features.calls`.

## 6. Два порта

Публичный (`6767`) и админский (`6768`) — **разные приложения Kestrel**.

Почему не один порт с `/admin`:

- `/api/admin/*` на публичном порту не существует физически — 404 от роутера,
  а не 403 от обработчика. Утёкшая ссылка на чат не открывает панель;
- админку можно привязать к `127.0.0.1` (`admin.localOnly`), не трогая чат;
- у панели свой пароль, независимый от аккаунтов чата. Владелец раздаёт доступ
  к чату, не раздавая доступ к панели.

## 7. Конфигурация и переопределения

Два слоя:

1. `config.ini` — то, что правит человек. С комментариями, с историей в git.
2. `data/overrides.json` — то, что правит админка. Плоский набор `ключ: значение`.

`KroshkaConfig.Load()` применяет INI, затем прогоняет каждое переопределение через
тот же парсер (собирая односекционный INI на лету), затем валидирует. Один код
разбора, никакого дублирования правил.

Почему так: правка `config.ini` из веб-панели уничтожила бы комментарии и порядок
ключей. Overrides-файл — это отдельный документ, который можно удалить, чтобы
вернуться к файлу.

Валидация не бросает исключений: битое значение → предупреждение в лог + дефолт.
Сервер, который не стартует из-за опечатки в цвете, — это плохой сервер.

## 8. Отказоустойчивость

Слои, снизу вверх:

**Файлы.** `FileStore.WriteAtomic` — temp → `File.Replace` с `.bak`. Если и это
не удалось, остаётся копирование поверх (хуже, но лучше потери). Чтение падает на
`.bak`, если основной файл битый.

**Карантин.** Нечитаемый JSON не удаляется: он переименовывается в
`<файл>.bad-<дата>`. Это сохраняет улики для разбора.

**Процесс.** `AppDomain.UnhandledException` и `TaskScheduler.UnobservedTaskException`
пишут crash-лог в `logs/crash-*.log` и не дают процессу умереть молча.

**Обслуживание.** Цикл каждую минуту: снять просроченные «печатает…», раз в 10 минут
почистить сессии, раз в `autoBackupHours` — бэкап. Любое исключение ловится и
пишется в лог; обслуживание не может уронить сервер.

**Порт.** Занят — пробуем `portFallbacks`. Пользователь видит в логе, какой порт
реально слушается.

**Клиент.** WebSocket переподключается с экспоненциальной задержкой (1 с → 15 с).
Мьютекс не даёт запустить второй экземпляр; второй запуск поднимает окно первого.

## 9. Логирование без App.config

Требование: Trace, в лог и в файл, без `App.config`, без задвоения листенера.

Задвоение возникает, когда `Configure()` вызывается дважды и каждый раз добавляет
новый листенер. Здесь:

```csharp
lock (Sync)
{
    if (_configuring) return;      // защита от реентрантности
    _configuring = true;
    try { Detach(); /* ... */ }
    finally { _configuring = false; }
}
```

`Detach()` делает `Trace.Listeners.Clear()` и диспоузит прежний файловый листенер.
Поэтому вызов из админки (смена уровня) не оставляет висящих писателей и не
удваивает строки.

Файловый листенер держит свой `StreamWriter` с `FileShare.ReadWrite`, ротация по
дате и размеру, старые файлы удаляются по `retentionDays`. Ошибка записи не
бросается наружу: листенер помечает себя мёртвым, если каталог исчез.

Запросы пишутся отдельно (`Log.Api`) и управляются `log.apiTrace` — можно держать
тихий лог и всё равно видеть трафик.

## 10. Интерфейс

### Один `web/` на все платформы

Десктоп (WebView2), браузер и будущий Android открывают одни и те же файлы. Нет
сборки, нет npm, нет `node_modules`: правка CSS видна после F5.

Кэш побеждён версионным токеном: сервер подставляет `?v=<штамп>` в ссылки на
скрипты и стили при каждой отдаче `index.html`. Штамп — самое новое время записи в
`web/`, поэтому он меняется ровно тогда, когда менялся интерфейс.

### Темы

Три набора CSS-переменных: `:root` (светлая), `[data-theme="dark"]`,
`[data-theme="oled"]`. Бренд-цвета приходят с сервера и вставляются как
`<style>`-блоки, **не** inline в `<html>`: inline-объявление перебивает любую
таблицу стилей, и переключение темы перестало бы работать. Это была реальная
ошибка, поймана при проверке в браузере.

### Звуки без файлов

`sound.js` синтезирует короткие ноты через WebAudio: восходящая терция на
«отправлено», нисходящая квинта на «получено». Ноль байт в репозитории, ноль
задержки загрузки, и звук можно перенастроить кодом.

`AudioContext` создаётся лениво и разблокируется на первом жесте — иначе браузер
запретит воспроизведение.

### Разметка

`renderText` сначала экранирует HTML, потом ищет URL и `@упоминания`. Порядок
важен: если линковать до экранирования, в `href` можно протащить `"` и выйти из
атрибута. Никакого markdown-рендерера — значит, нечего эксплуатировать.

## 11. Что осталось за рамками

- **E2E-шифрование.** Сознательно нет: оно ломает поиск, бэкапы и восстановление,
  а модель угроз здесь — «сосед по Wi-Fi», а не «сервер под контролем adversary».
- **Звонки.** Сигналинг готов, медиа — нет.
- **Федерация.** Один сервер = одна семья. Не распределённая система.
- **Индексация поиска.** Линейный проход по загруженным логам. Достаточно до
  десятков тысяч сообщений; дальше нужен обратный индекс.
